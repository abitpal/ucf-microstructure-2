Raw-event fair models

A Transformer and a GRU read the last 128 raw book events, with time encoded by each event's age in seconds, and predict the mid move at four horizons. Baselines use the handcrafted features.

What we found

  • The bitter-lesson result holds: a model reading raw events matches or beats hand-engineered features, and the margin is largest where the handcrafted features were weakest.
  • BTC 15m (held-out day Sep 23, unseen markets). GRU on the last 128 raw events: R² 0.251 / 0.158 / 0.119 / 0.018 at 0.1 / 0.5 / 1 / 10 s. Handcrafted LightGBM: 0.232 / 0.152 / 0.114 / 0.015; handcrafted MLP: 0.234 / 0.148 / 0.113 / 0.014. The Transformer ties LightGBM after 40 minutes (0.231 / 0.152 / 0.115 / 0.015) and edges past it after 75 minutes (0.233 / 0.154 / 0.116 / 0.018).
  • BTC perp, where the handcrafted features were built for binaries and transfer poorly: GRU 0.187 / 0.078 / 0.046 / 0.005 vs LightGBM 0.128 / 0.044 / 0.023 / −0.002, i.e. +47% at 0.1 s and roughly double at 0.5–1 s. The Transformer (only 1,300 steps in 25 min) roughly matches LightGBM.
  • When the mid does move, both sequence models call its direction correctly 82% of the time at 0.1 s, 71–72% at 1 s and 56–57% at 10 s on BTC 15m. On the BTC perp it is 65% / 57% / 52% for the GRU.
  • More compute keeps paying (scaling check). The same GRU trained for 60 min on 14 threads (11,777 steps, ~5 epochs) reaches test R² 0.262 / 0.164 / 0.123 / 0.018, up from 0.251 / 0.158 / 0.119 / 0.018 at 30 min. That is +13% over handcrafted LightGBM at 0.1 s and +8% at 1 s. Validation R² was still rising at the end. The GRU beats the Transformer on CPU because it runs ~3× more steps per minute at the same ~345k parameters; on a GPU that ordering may flip.
  • Continued Transformer. Resumed from the 75-min weights (not from scratch) for another 90 min (2,941 steps at batch 512, 30 threads). Validation R² at 0.1 s rose 0.224 → 0.244 → 0.252, and held-out test R² went from 0.233 / 0.154 / 0.116 / 0.018 to 0.244 / 0.158 / 0.119 / 0.017. That puts the Transformer level with the 30-min GRU and ahead of handcrafted LightGBM (0.232 / 0.152 / 0.114 / 0.015), still behind the 60-min GRU (0.262 / 0.164 / 0.123 / 0.018). It was still improving when the time cap hit; a full checkpoint (weights + optimiser) is saved and backed up, so it can be resumed again exactly.
  • Caveat for trading: these are R² on mid changes, with 76% of 0.1 s targets exactly zero. The notes already show this kind of edge is eaten by taker fees; the raw-event models make the forecast better, not the fee arithmetic.

Architecture

Tokens. One token per book event: a learned type embedding (delta / trade / snapshot), a learned embedding of the price offset from the current mid rounded to ticks (−50…50), and a linear map of side, add/cancel, scaled offset and standardised log size. Time. Each token gets the encoding of its age (seconds before the prediction time): sin/cos at 16 log-spaced periods from 1 ms to 1,000 s, plus log-age, a same-millisecond flag and a learned Time2Vec term. There is no positional index, so two events 3 ms apart look different from two events 3 s apart. Transformer: [readout] + [book-state token: top-5 sizes and offsets] + 128 events → 4 pre-norm layers, d=96, 4 heads → 4 outputs. GRU: same tokens in time order plus a log inter-arrival embedding → 2-layer GRU (160) → concatenated with the book-state embedding → 4 outputs. Both are trained with MSE on targets standardised per horizon, AdamW with warm-up and linear decay, and time-boxed.

Method

BTC 15-minute markets; train on Sep 18–21, validate on Sep 22, test on Sep 23 (new markets, new day). Targets are mid changes in ticks at 0.1, 0.5, 1 and 10 s. The raw model input is the last 128 events: type, side, add/cancel, price offset from the current mid in ticks, log size, and each event's age in seconds. Time is encoded with fixed log-spaced sinusoids (periods 1 ms – 1000 s) plus a learned Time2Vec term, instead of a token-position encoding. A book-state token (top-5 sizes and offsets) and a readout token are prepended. The GRU reads the same tokens in time order with log inter-arrival gaps added. Baselines (ridge, LightGBM, MLP) use the handcrafted window features at the same anchors.
